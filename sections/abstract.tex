\begin{abstract}
Tool calling has become the primary way large language models act on external environments, and its form is shifting from issuing one tool call per model turn toward Programmatic Tool Calling (PTC), where a model writes a program that composes many tool calls, control flow, and intermediate data processing inside a single block executed in a persistent runtime.
PTC reduces model-tool interaction rounds and expresses in-block control flow that a per-call protocol cannot, yet across program blocks it records execution as a linear history of code, standard output, and errors.
Such a history leaves the internal state of an execution untrackable, so whether a write took hold, which earlier value a later step depends on, and whether two results carry the same content all have to be recovered from raw text.
The cost is visible in accuracy, since PTC falls below plain per-call tool calling $14$ times over the seven benchmark settings and five backbones we evaluate and loses $34.5$ points on the worst one, so a programmatic runtime alone does not carry every setting.
To this end, we propose \method, which preserves the programmatic expressiveness of PTC and maintains a task-level dynamic execution graph built from real running traces.
Specifically, \method models the internal logic of each block as a typed subgraph of tool effects, artifacts, states, and failures, and models cross-block dependency as a multi-relation graph over which the agent declares an intent and chooses to continue, patch a failed step, replan a dependency path, or answer.
Unlike a linear history that flattens these relations into strings, the graph keeps them addressable, so the agent reads what an execution changed instead of re-parsing what it printed.
Experiments show that \method is the best method on every setting and every backbone, improving over Direct Tool Calling by $6.8$ points and over PTC by $6.3$ points while reading $1.7$ to $2.3$ times fewer input tokens.
\end{abstract}
