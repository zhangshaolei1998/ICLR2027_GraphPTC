\section{Related Work}

\textbf{Tool Calling and Programmatic Agents.}\quad
Tool-augmented LLMs have progressed from single-call protocols to programmatic execution.
Early work teaches models to emit one structured tool call per turn and interleave it with reasoning, as in Toolformer~\citep{schick2023toolformer}, ReAct~\citep{yao2023react}, ToolLLM~\citep{qin2024toolllm}, and Gorilla~\citep{patil2023gorilla}, and multi-agent frameworks such as AutoGen~\citep{wu2023autogen} and MetaGPT~\citep{hong2024metagpt} coordinate several such agents.
A parallel line expresses actions as code, starting from program-aided reasoning~\citep{gao2023pal,chen2023pot} and maturing into code-as-action agents that emit executable programs calling tools in a live interpreter, including CodeAct~\citep{wang2024codeact} and code-agent libraries~\citep{smolagents2025}.

\textbf{Enhancement of Tool Calling.}\quad
Direct tool calling has been improved along two directions.
One direction enriches the history the agent reads, where reflection turns past outcomes into natural-language advice~\citep{shinn2023reflexion,madaan2023selfrefine}, memory systems extend the usable context~\citep{packer2024memgpt,rasmussen2025zep,xu2025amem,sumers2024coala}, and provenance models in data management record how each result was derived~\citep{davidson2008provenance,herschel2017provenance}.
These additions index facts and entities for later retrieval and leave the execution itself as text.
The other direction changes how actions are issued, reducing the one-call-per-turn cost by batching dependent calls into a single program, and it arrives at programmatic tool calling, which runs a model-written program against many tools in one runtime~\citep{anthropic2025ptc}.

PTC buys expressiveness and fewer interaction rounds inside a block, but it still hands the model a linear transcript of code and output across blocks, so tool effects, artifacts, and state versions are untrackable and the dependency structure that execution induces is left for the model to reconstruct.
This is why PTC falls below direct tool calling $14$ times over seven benchmark settings and five backbones.
We propose \method to remove this bottleneck, maintaining a task-level dynamic execution graph that models in-block tool effects and cross-block dependencies and driving action selection from a bounded summary of that graph, so the agent keeps the efficiency of programmatic execution and recovers the reliability that a linear history loses.
